# Module 08 Facilitator Notes

## Teaching Emphasis

- Teach security as an execution control system, not a compliance add-on.
- Teach adoption as phased risk management, not a launch event.
- Require measurable gate criteria and named decision owners.
- Enforce stop conditions for unresolved blocking risks.

## Core Message

Safe adoption requires two systems working together:
security controls for actions and adoption controls for rollout.

## Common Student Mistakes

- writing abstract controls without actionable triggers
- defining approvals without naming decision owners
- using vague gate criteria like "looks ready"
- omitting rollback triggers
- allowing rollout with unresolved blocking failures

## Facilitation Prompts

- "What exact action is risky, and what blocks it?"
- "What evidence is required before this gate can pass?"
- "Who owns the go/no-go decision?"
- "What event forces immediate rollback?"

## Suggested Timing

- 10 min: concept framing and risk context
- 15 min: control stack and adoption gate design
- 20 min: dual-anchor exercise
- 10 min: debrief and implementation planning

## Exit Check

Before closing, ask each learner to provide:

- one complete security control map for each anchor
- one complete adoption gate plan for each anchor
- one explicit rollback and escalation rule they will implement
