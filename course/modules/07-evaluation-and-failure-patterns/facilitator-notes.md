# Module 07 Facilitator Notes

## Teaching Emphasis

- Treat evaluation as a designed workflow component, not a final step.
- Enforce measurable pass/fail gates.
- Require reusable failure pattern IDs.
- Require recovery evidence before approval.

## Core Message

Reliable workflows separate generation from evaluation and convert
recurring failures into explicit prevention and recovery patterns.

## Common Student Mistakes

- defining goals but not pass/fail thresholds
- running checks only after all work is complete
- recording failures without root cause or detection signal
- allowing approval with unresolved blocking failures
- skipping recovery evidence in progress logs

## Facilitation Prompts

- "What exact condition fails this checkpoint?"
- "How do you detect this failure before approval?"
- "What evidence proves recovery worked?"
- "What pattern ID should this failure map to next time?"

## Suggested Timing

- 10 min: concept and framing
- 15 min: gate design and failure anatomy
- 20 min: dual-anchor exercise
- 10 min: debrief and artifact updates

## Exit Check

Before closing, ask each learner to provide:

- one complete evaluation loop for coding anchor
- one complete evaluation loop for knowledge-work anchor
- one embedded failure pattern catalog they can reuse immediately
